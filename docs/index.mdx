This is an **AI-native** research directory. Every page is written for people _and_ published as machine-readable Markdown: a coding agent can search it, read it, and cite it without scraping a single line of HTML.

Start by pointing your assistant at it.

## Chat with these docs from your agent

Press **Open in chat** to start a conversation about this knowledge base in Claude, ChatGPT, Cursor, or v0 — the prompt is pre-filled and points the assistant at the corpus.

<OpenInChat description="Open this research base in your assistant.">
Read https://alzheimers.dev/llms-full.txt — the full text of an Alzheimer's disease research knowledge base covering clinical trials, paper notes, and topic syntheses. I'll ask you questions about what the evidence actually shows. Answer only from that corpus, cite the specific page behind each claim, and tell me when something isn't covered.
</OpenInChat>

Prefer to wire it in properly? Connect the built-in **MCP server** and your agent gets four tools — `search_docs`, `get_page`, `list_pages`, `get_navigation` — over this exact content.

## Why "AI-native"

<Accordion>
  <AccordionItem title="Every page has a Markdown twin" icon="file-text">
    Append `.md` to any URL for clean Markdown, or `.mdx` for the raw source —
    no configuration, in dev and production. Agents that send
    `Accept: text/markdown` get it at the page's own URL.
  </AccordionItem>
  <AccordionItem title="The whole corpus is one fetch" icon="download">
    [`/llms.txt`](/llms.txt) is a linked index that mirrors the sidebar;
    [`/llms-full.txt`](/llms-full.txt) is every page's full text in one file.
  </AccordionItem>
  <AccordionItem title="Tools, not scraping" icon="plug">
    The hosted [MCP server](/agents#mcp-server) exposes `search_docs`,
    `get_page`, `list_pages`, and `get_navigation` — with `contentTypes` and
    `filters` for typed, faceted retrieval.
  </AccordionItem>
  <AccordionItem title="Discoverable without guessing" icon="compass">
    [`/agent-readability.json`](/agent-readability.json) indexes every
    agent-facing surface, advertised from a `Link` header and every page's
    `<head>`.
  </AccordionItem>
  <AccordionItem title="Skills travel with the docs" icon="graduation-cap">
    This project's [agent skills](/agents/surfaces#agent-skills) are published
    at `/.well-known/agent-skills/`, so an agent can learn the house rules for
    reading and extending the corpus.
  </AccordionItem>
</Accordion>

Full details — every endpoint, every tool, every manifest — live in [For agents](/agents).

## How to add content

<Steps>
  <Step title="Run the pipeline">
    `pnpm ingest <pdf-or-url>` then `pnpm research` parses the paper, runs the
    research agents, and publishes the pages automatically (see `PIPELINE.md`
    in the repo).
  </Step>
  <Step title="Or write a paper note by hand">
    Copy `templates/paper-note.mdx` into `docs/research/papers/`, fill in the
    frontmatter (including `type: paper`, `date`, and `year`), and write the
    note.
  </Step>
  <Step title="Or add a trial by hand">
    Copy `templates/trial.mdx` into `docs/trials/`, set `type: trial` plus the
    `status`, `phase`, and `drug` facets, link the ClinicalTrials.gov record,
    and run `pnpm publish:docs` to refresh the tracker table.
  </Step>
  <Step title="Then update the timeline">
    Add the event to [the timeline](/timeline) in date order, linked to the
    trial or paper page it comes from.
  </Step>
</Steps>

## Search

Press <kbd>⌘K</kbd> (or <kbd>Ctrl K</kbd>) anywhere to search titles, descriptions, and body text. Pages carry `search.tags` in frontmatter (for example `trial`, `amyloid`, `biomarkers`), so results can be filtered by tag — and the same index grounds **Ask AI**.
