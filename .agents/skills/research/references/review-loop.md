# Review loop

`pnpm research` exiting 0 means the agents returned parseable JSON. It does not mean the pages are
right. Work this checklist before reporting.

## 1. Reviewer output — `enriched/<id>/04-review.json`

```bash
node -e 'const r=require("./enriched/<id>/04-review.json");
console.log(r.notes_for_editor);
console.log(r.fact_check.filter(f=>f.status!=="verified"));'
```

| Signal | Meaning | Action |
| --- | --- | --- |
| `notes_for_editor` non-empty | The reviewer could not settle something | Resolve each one, or carry it into your report verbatim. `publish` also prints these at the end. |
| `fact_check[].status: "corrected"` | A stage got a number wrong and the reviewer fixed it | Confirm the correction is on the page, not just in the JSON. |
| `fact_check[].status: "unverified"` | Nobody could confirm it | It must not be stated as fact on the page. Fix `caveats_md` or drop the claim. |
| `fact_check[].status: "disputed"` | Sources disagree | The page must show both sides. |

## 2. Registry truth — `enriched/<id>/02-trials.json`

- `discrepancies[]` is the highest-value output in the whole pipeline: where the document's claims
  diverge from the registry. Every entry must survive onto the published page. If one is missing,
  that is a bug worth reporting.
- `trials[].verified: "unverified"` → the registry record was never fetched. Fetch
  `https://clinicaltrials.gov/api/v2/studies/<NCT>` yourself and correct it, or flag it.
- New NCT ids here that `discover` marked `already_documented: false` are next-round work.

## 3. Analysis sanity — `enriched/<id>/01-analysis.json`

- `parse_quality.score` below ~6 → the PDF converted badly. Read `raw/<id>/document.md` around the
  numbers you care about before trusting any of them. Scanned/image-only PDFs need OCR (`PIPELINE.md`).
- `doi`/`pubmed_url` null → identifiers were never verified. Do not let a page cite an unverified id.
- `red_flags[]` and `funding_and_conflicts` render into the page's Critical review block
  automatically — verify they actually appear rather than restating them.

## 4. The diff

```bash
git status --short && git diff --stat docs/
git diff docs/timeline/index.mdx
```

- **New pages** — paper notes land in `docs/research/papers/`, trial pages in `docs/trials/`; both
  index tables are regenerated by `publish`. Confirm nothing duplicates an existing page, including
  the hand-written topic pages in `docs/research/`. Duplication means the reviewer was not given
  the right `SITE_PAGES` context, or two documents cover one subject and should be merged by hand.
- **Timeline** — milestones only. A routine result or a review contributing a timeline entry is
  usually wrong; remove it. `publish` reports `section "X" has no <Steps> block — add manually`
  when it cannot place an entry, and it will not guess. Place it yourself.
- **Index tables** (`docs/trials/index.mdx`, `docs/research/papers/index.mdx`) are regenerated from
  the pages themselves — check the row counts match what was published.
- **Overwritten pages** — republishing a document overwrites its generated pages. If a diff wipes
  hand-written prose, that prose belonged in a non-generated page or in the prompts.

## 5. Fixing the right layer

| Problem | Fix |
| --- | --- |
| One document's output is wrong | `pnpm enrich --force <id>` after fixing the input, or edit the page. |
| A stage is systematically wrong | Edit `pipeline/prompts/<nn>-*.md`, then `pnpm enrich --stage <nn>-<name>` to re-run just it. |
| Page structure/layout is wrong | `pipeline/publish.mjs` — the renderer owns structure. Never patch generated pages to work around it. |
| Bad source got in | Delete `sources/<file>`, `raw/<id>/`, `enriched/<id>/`, and the pages it produced; note why in your report. |

## 6. Report

State plainly: documents ingested, pages created or changed, sources screened out and why, trials
still undocumented, non-OA papers cited but not ingested, and every unresolved `notes_for_editor`.
Do not commit unless asked.
